# AGENTS.md — стандарты работы над uwu-ai-agent

Это инструкция для AI-агентов (и людей), работающих над **этим** репозиторием.
Целевой сервис — AI-агент (консультант покупателей) для проекта UWU
(ядро учёта торговли/склада, `https://github.com/AleksandrVoinitsky/UWU.git`).

## 1. Что это и что НЕЛЬЗЯ делать

- **uwu-ai-agent — отдельный сервис и отдельный контейнер.** Он встраивается
  на тот же хостинг по модели «1 репозиторий = 1 контейнер» рядом с ядром UWU.
- **Агент — клиент REST API ядра UWU.** Он НЕ пишет напрямую в БД ядра, НЕ
  дублирует бизнес-логику (проведение, себестоимость, остатки) и НЕ имеет
  зашитых промптов (кроме жёсткой защитной рамки).
- **Промпты, инструменты, ключи, одобрения, наблюдение управляются из админки
  ядра UWU** (`/admin/agent/*`). Агент загружает их через API (кэш с
  инвалидацией), а не хранит в своём коде.
- **Источник истины по доменным решениям — `docs/ai-agent.md` в ядре UWU**
  (архитектура, граф, HITL-пороги, БД/API, тесты). При противоречии —
  уточнить у автора, а не переобсуждать архитектуру заново.
- Не менять ядро UWU из этого репозитория: это отдельный репозиторий со своей
  рабочей папкой `C:\UWU`. Всё, что требует изменений ядра (например,
  эндпоинты `/api/agent/*`, потребляемые агентом), фиксируется как
  **контракт/зависимость** (см. `docs/integration.md`) и согласуется с автором.

## 2. Стандарты кода (как в ядре)

- **Python 3.13**, FastAPI, LangGraph/LangChain, pydantic v2.
- **TDD**: тесты обязательны, пишутся до/вместе с кодом, гоняются перед деплоем.
- **SOLID + чистый код**: слоистая архитектура, направление зависимостей
  строго сверху вниз (`api → services/graph → clients/core`).
- **Разбивай код на файлы с осмысленными именами**; не точечные правки, работай
  от общего к частному (сначала архитектура).
- **Документация в Markdown** в `docs/` с перекрёстными ссылками на каждый
  модуль/функцию: для каждого — «назначение» (бизнес) и «техническое описание».
- **Зависимости пинятся** (`requirements.txt` + `pyproject.toml`). Не изобретай
  то, что можно взять из проверенных пакетов.
- Линтер **ruff**, type-check **mypy** — как в ядре.
- **Русский/английский** язык интерфейса/ответов предусматривается; ответы
  агента — на языке пользователя.

## 3. Структура репозитория

```
app/
├── core/        # конфигурация (config.py), логирование
├── clients/     # HTTP-клиенты (uwu.py — клиент REST API ядра)
├── llm/         # фабрика LLM-моделей (OpenAI-совместимый API)
├── graph/       # LangGraph: state.py, nodes.py, builder.py
└── api/         # control-plane (routes.py), main.py — точка входа
tests/           # pytest (TDD)
docs/            # Markdown-документация с перекрёстными ссылками
```

## 4. Безопасность

- API-ключ агента — ограниченные права, хешируется в ядре, показывается один раз.
- Промпт-инъекции: жёсткая рамка в системном промпте; ввод пользователя — данные,
  а не инструкции; инъекции логируются в `agent_runs`.
- Минимальные привилегии инструментов: права проверяет **ядро**, а не агент.
- HITL по порогу: чтение — авто; мутирующие ниже порога — авто; выше — одобрение.
- Rate limiting инструментов и входного потока.

## 5. Рабочий процесс

- Работа через Git/GitHub, коммиты с осмысленными сообщениями, безопасная
  разработка. Первый коммит уже сделан; дальше — атомарные коммиты по фичам.
- Тесты в Docker периодически, не слишком часто; основная цель — разработка.
- При нехватке прав или необходимости уточнения — **остановись и явно напиши
  просьбу автору** (см. пункт 1 про изменения ядра).

## 6. Ключевые решения (зафиксированы в ядре, не пересматривать)

1. Надзор (HITL) — по порогу суммы/типа действия.
2. Checkpointer — PostgreSQL, отдельная схема `agent`.
3. Модель — OpenAI-совместимый API (конфигурируемый) + SSE-стриминг.
4. Отвечает по умолчанию агент, оператор перехватывает вручную.
5. Векторный поиск — каталог товаров + память покупателей (pgvector).
